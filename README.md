# ✈️ 旅遊行程規劃工具

一個純瀏覽器的旅遊行程規劃工具，無需安裝、無需帳號，開啟即用。支援雲端共用，可與家人或朋友共同查看行程。

## 功能總覽

### 🗓 行程規劃
- **多行程管理**：點頂部「📋 行程」按鈕可新增、切換、刪除多個旅行計畫，各自獨立儲存
- **旅行日期**：設定出發日期後，每天標籤自動顯示實際日期（如 `6/15(日)`），方便確認星期幾
- **多天行程**：可新增多個天數，每天獨立管理景點
- **景點管理**：新增、刪除景點，可設定名稱、停留時間、備注
- **景點分類**：點景點左側圖示可標記分類（景點、餐廳、購物、交通樞紐、住宿、體驗活動、其他），分類顏色顯示於卡片色條與時間軸圓點，支援全部四種主題
- **交通方式**：景點之間可選擇步行、開車、大眾運輸等交通方式，並設定預估交通時間
- **時間軸**：自動根據出發時間 + 停留時間 + 交通時間計算每個景點的抵達與離開時間
- **拖曳排序**：直接拖曳景點卡片調整順序
- **飯店設定**：每天可設定出發地（飯店）與目的地（飯店）名稱
- **撤銷／重做**：按 `Ctrl+Z` / `Cmd+Z` 撤銷，`Ctrl+Y` / `Cmd+Shift+Z` 重做；頂部工具列亦有對應按鈕，最多保留 50 步歷史

### 📁 匯入 / 匯出
- **匯出 JSON**：將目前行程儲存為 `.json` 檔案備份
- **匯入 JSON**：從備份的 `.json` 檔案還原行程

### 🔧 批次工具
設定面板提供兩個批次操作，皆透過免費 OpenStreetMap 服務（Nominatim + OSRM）：

- **🔍 查座標**：列出所有景點並標示是否已定位（🟢 / 🔴），可勾選批次查詢地理座標，讓匯出 KML／CSV 的定位更精準。
- **⏱ 自動填通勤**：一鍵估算各段交通時間並填入。可在設定面板的「填通勤」對所有天執行，或在每天底部的「⏱ 自動填通勤」只處理當天；支援選擇是否**覆蓋已有時間**，並可設定每段的**緩衝時間（分鐘）**，供停車、找路等預留。大眾運輸以開車路線近似估算。

### ☁️ 雲端共用
行程可上傳至雲端，分享給家人或朋友查看、匯入。共用區分為**公開**與**非公開**兩種模式。

#### 公開行程
所有人都可以在公開分頁看到，適合完全公開分享。

#### 非公開行程（暗號分組）
只有知道暗號的人才能查詢，適合家族旅遊或小群體共用。

**範例：**
> 家族北海道旅遊，全家人共用一個暗號 `hokkaido2025`。
> 爸爸上傳行程時選「非公開」並輸入暗號 `hokkaido2025`；
> 其他家人在非公開分頁輸入同樣的暗號 `hokkaido2025`，就能看到爸爸分享的行程。
> 同一個暗號可以有多筆行程，方便不同人各自上傳版本再互相比較。

上傳時需設定**刪除密碼**，之後若要修改（覆蓋）或刪除該筆雲端行程，需輸入當初設定的密碼才能操作。

點行程旁的**「管理」**按鈕可進行：
- **更換密碼**：輸入舊密碼驗證後設定新密碼
- **刪除行程**：輸入密碼確認後從雲端移除

上傳成功後會自動產生**分享連結**（`?import=...`），可直接傳給對方；對方開啟連結即會跳出確認視窗並自動匯入行程。點行程旁的**「分享」**按鈕可隨時重新複製連結，不需重新上傳。

### ⚙️ 設定
- **版面配置**：A 頁籤 / B 側邊欄 / C 垂直捲動，三種版面隨喜好切換
- **主題**：淺色 / 深色 / 跟隨系統
- **預設交通方式**：設定新景點之間預設的交通方式

## 開發說明

專案採**多檔 ES modules、零建置**架構：`index.html` 直接載入 `js/app.js`，其餘模組以原生 `import` 串接（`js/render/`、`js/services/`、`js/state.js` 等），CSS 拆為 `css/tokens.css`、`css/layout.css`、`css/components.css`。沒有打包步驟，改完存檔即生效。

### 本機啟動

ES modules 需經 HTTP 提供，無法用 `file://` 直接開。啟動本機開發伺服器：

```bash
npm run serve      # → http://localhost:8080/
```

此指令走專案內的 `serve.py`，它對每個回應送出 `Cache-Control: no-store` 等停用快取的標頭。**用意**：零建置架構的檔案沒有內容 hash，瀏覽器很容易把舊版模組／CSS 快取在記憶體，造成「改了卻沒更新、要 `Ctrl+Shift+R` 才生效」。停用快取後，改完程式**一般重整（F5）即為最新**。

> 若手邊沒有需求，用 `python3 -m http.server 8080` 也能跑，只是會遇到上述快取問題。

### 正式環境（GitHub Pages）的快取

GitHub Pages 由 CDN 提供，與本機不同：它自帶一層邊緣快取，push 新 commit 後通常會在短時間內更新。實務上一般使用者重訪很快就會拿到新版，**目前不需要**為此在每個 `import` 加版本查詢字串（維護成本高）。

這只是目前判斷，不是硬規定——若日後出現「已部署但使用者長時間看到舊版」的實際狀況，再視情況導入版本號機制（例如集中一個 build 版本常數、對入口資源加 `?v=` 查詢字串）即可。以當下實測行為為準。
